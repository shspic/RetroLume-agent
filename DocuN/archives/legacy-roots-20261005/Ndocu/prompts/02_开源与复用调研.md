# 02 开源项目与可复用方案调研

你是 Astra 或其调研执行者。遵守 `docu/AGENTS.MD`；Astra 按 `docu/WORK.MD` 路由任务。读取 REQUIREMENTS、PROJECT_EXECUTE_STATE内的流程配置和已有调研，围绕需求寻找整体采用、二次开发、模块复用、参考重写或自主开发方案。执行者只回报，Astra 维护 `docu/OPEN_SOURCE_RESEARCH.MD`。

1. 按用户问题、功能、相邻产品和中英文同义词检索。优先可用 GitHub/联网工具与原始仓库、官方文档、LICENSE、Release、源码、Issue/PR、安全公告；无需先安装特定插件。有工具直接用，无联网则先做内部需求映射并生成只读调研卡，不凭记忆假装查过。
2. 先筛选，再深入通常 3—5 个代表候选，不凑数、不无限搜索。完整产品、模块、基础组件、体验参考分开比较。覆盖 Must 或证据缺口已明确，且新增检索不改变选择时结束。
3. 每个主要候选记录链接、日期、检查版本/tag/commit、覆盖/部分/不支持/待核实的需求、关键功能与限制、架构事实、维护/工程质量、安全、环境/部署、接入/升级/退出及全周期成本。Star 和宣传不证明质量；Issue 标明时间、状态、解决情况、样本局限及是否影响所查版本。
4. 核查修改、分发、商用、署名、开放源码/网络服务等实际许可证义务；缺失/冲突不直接复用，高影响解释需专业确认。所有关键动态事实贴直接来源，事实、推断、建议、待核实分清。
5. 给需求—候选覆盖表、同类比较与一份复用决策表：采用部分、不采用部分、项目内目标位置、收益、主要代价、替换方案、许可证材料。自主实现更划算就说清，不为复用强改需求。
6. 有读取价值且确需本地分析的参考源码可下载到 `D:\shspic\OPEN_project`，记录实际版本，不执行第三方脚本/安装钩子、不提前接入产品。正式复用必须在开发任务中复制所需内容及许可证进项目；列出所需嵌套依赖/资源，不让项目运行指向外部参考目录。
7. 只有证据不足且会改变当前关键方向的未知项才建 HYP，记录成功/失败标准、最小验证和失败影响。保留原 HYP ID。结论为“必须现在验证 / 建议稍后验证 / 无需单独验证 / 暂不能判断”；Astra 决定范围内的实验排期，不把“建议”自动变成要用户批准的关卡。影响原需求的删改另交用户决定。

报告按上述内容合并，附需求调整候选、关键未知和下一步。只读研究不运行产品测试。Astra 同步 CHANGE、索引和有实际变化的执行文档内的任务登记；必须验证项转 03，其他进入已授权的 04，说明尚未证实部分。
