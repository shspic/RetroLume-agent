# 08 整体集成验收与发布准备

遵守 `docu/AGENTS.MD`。Astra 依 WORK 划定验收范围，输出完整可复制的测试、审计、验收卡供用户转交；实际检查由接卡执行者完成，必需独立审计使用隔离会话。Astra 收到回传后核对证据并最终登记结论；既有有效证据充分时可直接裁定，不为出卡重复检查。目标是判断候选版本是否满足要求，不是证明它一定成功。业务实现只读，缺陷另派修复。

## 固定对象和证据

读取有效需求/架构/执行状态、当前代码或产物、启动/测试入口、既有报告及已获授权的测试环境。冻结 BASE-CHECK：版本、分支/提交及未提交差异、环境/工具/依赖/配置/数据状态、日期；没有 Git 用可复核的文件/产物快照，不要求所有文件逐字哈希。对象无法识别则无法给正式通过结论。

实际改变代码、配置、数据结构、接口、依赖、部署或用户行为时，结束旧轮并追加新 ROUND，不能覆盖历史。证据适用性按 WORK 判断：未受影响且可证明有效的结果引用原位置，改变部分补测；必须覆盖当前候选的集成和核心流程，不能只靠旧单元测试拼出“整体验收通过”。

## 按范围验收

为适用检查使用 WORK 的 `*-CHECK` 编号，记录需求/实现位置、标准、方法、证据、状态和缺陷。每项 Must 有客观验证。以下是覆盖维度，不是每次全跑的命令清单：

- 环境/可复现性：配置模板、敏感项隔离、安装说明、初始化、启动和停止；必要时独立环境准备卡，验收者不自行升级依赖/改锁文件。
- 构建/静态检查、自动化测试、回归：针对实际风险、适用门槛和证据缺口；格式检查使用只检查模式。
- 核心用户流程、模块/外部集成：正常与失败、超时、重试、降级、空/非法输入、重复操作、部分成功和恢复；Mock/沙箱与真实调用分清。
- 数据/恢复：准确性、一致性、兼容、迁移、备份恢复、中断、清理；权限/隐私：认证、授权、用户隔离、输入/文件处理、注入/路径、密钥、日志、外发和删除。
- 性能/容量：仅有需求或真实风险时按环境/规模/并发/基准测试，不与其他资源竞争测试并行。
- 部署/发布准备：版本产物、环境、健康检查、监控、迁移、备份、回滚触发和发布后验证；文档与实现一致。
- 项目自包含：源码/资源/许可证位于项目内，无外部参考库、错误经验库、临时实验、绝对本机路径、外部链接等功能依赖；在合适的独立位置验证复制/安装后的核心启动与运行，不动外部参考库或经验库，优先复用本轮可复现运行证据。检查对象是本次开发的产品，不是提示词套件的目录。

失败不妨碍其他独立安全检查。测试、审计按难度/风险路由，Astra 不默认全包。任务卡及结果由用户转交；额外检查必须真机、登录或业务判断时才请用户操作；给具体步骤、成功标志、失败恢复和非敏感回传项，不索取密码或验证码。

## 缺陷与结论

DEF严重度：P0＝重大安全/数据损失/泄露、无法构建启动或必然发布失败；P1＝Must/主流程/关键集成失败且无合理替代；P2＝非核心且有替代或局部文档问题；P3＝轻微体验/文案/维护。记录复现、影响、证据、状态、唯一修复路线。原缺陷回07，优化直接回归回09，需调整修复计划先06；因果不清先只读诊断。

四类结论：

- **通过**：Must/核心流程有有效证据，必要检查、强制人工检查和必需独立审计完成，无开放P0/P1，发布与回滚条件明确。
- **有条件通过**：仅P2/P3或不影响核心的限制，有替代且用户已明确接受影响和条件。待用户接受不能提前这样写。
- **不通过**：已知P0/P1、核心失败、数据/严重安全风险，或无法安全构建/启动/发布/回滚。
- **无法判断**：关键对象、环境、证据、人工结果或独立审计缺失；已有确定失败时写不通过并同时列缺失。

Astra 写 `docu/ACCEPTANCE_REPORT.MD`：每轮快照、范围、检查/追踪、原始证据位置、DEF、人工/审计、未验证、结论及下一步。隔离执行者只给候选报告，不写最终状态。另写 `docu/RELEASE_RUNBOOK.MD`：当前项目的验收/配置/未来发布/健康检查/回滚步骤，前置条件、真实已知命令、失败处理和必要人工动作；未知命令标待确认，不编造可执行性。

同步 CHANGE/索引/执行状态及实际架构变化。报告完整可标“本轮记录完成”，不等于验收通过。验收达到可接受结论且有基线采用依据时将架构/执行文档更新为已定稿，保持文件名和历史。本次交付目标满足即结束，不自动进入竞品复盘；有获准优化时可直接转09，09返回的版本完成相应OPT验收。生产发布必须独立任务、明确环境/范围/备份/回滚授权，本阶段只准备。
