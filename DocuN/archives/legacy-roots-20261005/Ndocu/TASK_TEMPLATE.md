# TASK 任务卡模板

由 Astra 填写后保存为 `Ndocu/tasks/TASK-XXX.md`，同时将完整卡放进回复中一个独立可复制文本块，供用户粘贴给执行 Agent；块外说明接收客户端/模型及执行顺序。所有正式任务同一合同，删去不适用空行，保留能改变执行结果的信息；不能只交链接、摘要或“按之前讨论做”。

```text
你是本卡的执行 Agent。按下列目标和范围完成任务，结束后输出供用户带回 Astra 的结果包；不接管项目编排。
任务：TASK-XXX；类型：调研/文档/开发/测试/审计/验收/诊断
关联：需求、架构、STEP、父TASK、HYP/SPIKE/DEF/OPT（适用项）
执行者：客户端 + 实际模型或待核实标签；强/中/低；路由理由：
项目根目录：；基线版本/提交/差异：；授权依据：

目标与现状：一个主要结果；当前问题、必要背景、已有决定和失败证据。
上下文：先读根入口和 docu/AGENTS.MD；按顺序列路径/章节或附必要原文；接口、预期行为、相关实现/测试、证据位置。
边界与约束：允许读取/写入；禁止范围；兼容、权限、数据、依赖限制。
协作资源：前置任务；独占文件/分支；端口、数据、账号、缓存/输出/服务；可并行对象或必须串行原因。
交付与验收：具体产物/路径；正常和关键异常的可观察成功条件；文档更新建议。
复用/经验（适用时）：复用源码及必要资源的项目内落点；相关已验证经验摘录/索引；有价值的新解法候选交Astra按WORK写入D:\shspic\错误记录，禁止产品依赖外部库。
验证：现在为何需要；方法/真实已知命令（未知则先定位）；已有证据可否复用。
测试子项（实际测试必填）：执行档位；被测范围/快照/环境/样本；预期/失败；时间或样本/尝试上限；结果目录；停止条件。
审计（适用时）：风险级别；是否必须隔离新Session；独立原始证据包；不得继承执行聊天和自评。
停止/升级：完成即停；超范围、高风险新发现、两次修正仍失败或投入上限到达，带证据交回Astra。
返回：TASK及关联ID；完成/部分/阻塞/失败建议；实际文件差异与作用；实际命令/操作、结果和证据；未验证和风险；需求/架构偏差；待同步文档；仅必须人工操作；下一步。
回报位置：有写权限时保存 Ndocu/results/TASK-XXX-result.md，并在回复中给出一个完整可复制结果块，包含上述返回项、证据路径及必要摘录，供用户原样带回 Astra；无写权限时直接给结果块并标未保存。不得填写Astra最终验收结论。
```

只做文档时，验证写“覆盖与一致性检查”，不填产品测试。只运行已定测试时，可以用低档，但测试预期、资源安全与风险分析必须充分。需要强档裁定的安全结论不能由低档“命令退出成功”替代。
