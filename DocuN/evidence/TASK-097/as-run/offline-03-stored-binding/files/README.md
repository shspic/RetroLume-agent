# RetroLume 本地工程入口

本目录为 RetroLume 本地工程。下列启动说明沿用 STEP-024 已交付的本地资料入口；后续内部业务切片和未完成范围以 [架构动态文档](DocuS/架构动态文档.MD) 与 [执行动态文档](DocuS/执行动态文档.MD) 为准。内部调用验证通过不代表公开业务页面、真实模型服务或完整产品已经交付。

## 环境与依赖恢复

使用 Python 3.12、Node 24 和 npm 11。后端依赖由 `backend/requirements.lock` 固定；在 `backend/` 创建项目内 `.venv` 后执行：

```powershell
.\.venv\Scripts\python.exe -m pip install --only-binary=:all: -r requirements.lock
```

前端在 `frontend/` 使用精确 `package-lock.json`：

```powershell
npm.cmd ci --ignore-scripts --no-audit --no-fund
```

这些命令只重建项目内依赖，不升级锁版本。已安装包随自身发布的许可证与版权声明保留在项目内依赖目录；仓库不提交 `.venv` 或 `node_modules`。

## 本地配置与启动

设置两个互相独立、已存在的绝对目录：`RETROLUME_DATA_DIR` 与 `RETROLUME_BACKUP_DIR`。资料与备份可位于项目外，但它们是数据配置，不能指向外部源码。可参考 `config/local.env.example`，不要提交真实路径、连接串或密码。

若要连接既有本地 PostgreSQL，再在当前会话设置 `RETROLUME_DATABASE_URL`，或在 `config/database.local.json` 保存仅本机使用的私有配置（该文件已忽略）。应用不会自动创建数据库或迁移用户库。`deploy/initialize-materials.py` 仅供另行明确批准的新库首次初始化。模型调用需要完整配置和用户显式动作，读取、零费新建及刷新不会启动模型。

开发健康检查可在设置上述两个目录后运行：

```powershell
.\deploy\start-backend.ps1
```

访问 `http://127.0.0.1:8000/health`。`start-local.cmd` 会在数据库配置有效且容器镜像一致时启动既有本地容器；它只停止本次启动的容器和应用。构建后的前端由后端同源提供；开发前端可在 `frontend/` 运行 `npm.cmd run dev`，实际模型动作使用同源工作区。

## 活动与首次学习

活动配置参考 `config/activity.example.json`，在本机私有 `config/activity.local.json` 中分别配置活动限额和模型服务。示例占位值不会激活调用。服务密钥仅由配置指定的环境变量读取，不能填入目标、资料或浏览器。活动读取仅依赖存储层，零费新建需要活动限额层，首次学习及续问另需完整模型服务层。

新学习能力默认关闭。启用时增加 `learning` 对象，其 `profile` 必须为 `learning.v1`，`output_tokens` 为1至256的整数，且不超过活动与模型服务的输出上限。活动和服务的请求字节、输出、费用预留、次数及运行额度仍各自生效；坏配置或超限会关闭对应入口，不采用免费替代预算。

在活动工作区选择就绪资料并新建活动，此时不产生模型费用。TXT/MD需为当前未删除版本，PDF需完成有效物理页核对；用户补充保留独立来源身份。检查资料范围、服务用途与四类账面限额，输入具体目标并勾选确认，然后点击“开始学习”。目标最多1024字和4096 UTF-8字节，不能通过目标授权路径、工具或范围外资料。

一次动作最多检查10个来源、合计5 MiB原件和512个候选片段，PDF最多50物理页。有限词项查询最多24项，选取最多8段、合计12000字和24000 UTF-8字节的证据；超过上限会提示缩小范围。当前没有向量检索，中文按实际词项规则匹配，可能漏召回。同名歧义、无候选会先提示补充；调用后也可能得到必要追问、证据不足或来源冲突，不自动循环补全答案。

成果从活动存储读取，展示答案或必要提示、确认目标、引用和能力限制。点击“查看引用”回查该版本的真实行段；PDF显示物理页并区分原文和用户补充。版本被替换或来源失效时明确不可用，不拿新版本替代旧引用。引用身份与位置合法不代表结论已独立证实，真实供应商的整体语义质量仍待获准样本验证。

从当前学习成果点击显式续问，输入问题并确认发送。它保留原目标，用新的受控操作重新检查范围、版本和预算；已有成果不被覆盖。普通模型成果保留原继续入口。模型文字只作文本显示，不执行HTML、脚本或工具。

## 刷新、取消与未确认动作

首次及续问会先在本机意图台账记录业务键和输入，再发送一次显式请求。刷新和切换只查询持久事实；正文不依赖本机缓存恢复。首次槽位由服务端稳定绑定目标和范围，双击或换客户端键不会产生第二个首次成果；异文会提示冲突，修改目标应显式续问或新建活动。

未确认横幅可能表示请求未到达，也可能表示服务器已执行。先点击核对；只有用户点击同键重试才会再发请求，已知持久操作仅返回事实。真实未知状态不自动换键或重发，也不自动退还预留。放弃仅移除本机意图，不取消服务器、不退款或删除已保存成果。

旧格式未确认意图继续可核对。意图台账损坏时暂停依赖恢复的新写动作，读取和两步确认取消仍可用；核对服务器事实后可通过浏览器站点存储工具修复或移除本机台账，此举不改变服务器状态。取消停止本机受监督后续执行，无法撤回已经发给远端的请求；保留已有有效成果及真实账面事实。
