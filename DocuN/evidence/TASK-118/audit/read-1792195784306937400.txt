11: ## 环境与依赖恢复
12: 
13: 使用 Python 3.12、Node 24 和 npm 11。后端依赖由 `backend/requirements.lock` 固定；在 `backend/` 创建项目内 `.venv` 后执行：
14: 
15: ```powershell
16: .\.venv\Scripts\python.exe -m pip install --only-binary=:all: -r requirements.lock
17: ```
18: 
19: 前端在 `frontend/` 使用精确 `package-lock.json`：
20: 
21: ```powershell
22: npm.cmd ci --ignore-scripts --no-audit --no-fund
23: ```
24: 
25: 这些命令只重建项目内依赖，不升级锁版本。已安装包随自身发布的许可证与版权声明保留在项目内依赖目录；仓库不提交 `.venv` 或 `node_modules`。
26: 
27: ## 本地配置与启动
28: 
29: 设置两个互相独立、已存在的绝对目录：`RETROLUME_DATA_DIR` 与 `RETROLUME_BACKUP_DIR`。资料与备份可位于项目外，但它们是数据配置，不能指向外部源码。可参考 `config/local.env.example`，不要提交真实路径、连接串或密码。
30: 
31: 若要连接既有本地 PostgreSQL，再在当前会话设置 `RETROLUME_DATABASE_URL`，或在 `config/database.local.json` 保存仅本机使用的私有配置（该文件已忽略）。应用不会自动创建数据库或迁移用户库。`deploy/initialize-materials.py` 仅供另行明确批准的新库首次初始化。模型调用需要完整配置和用户显式动作，读取、零费新建及刷新不会启动模型。
32: 
33: 开发健康检查可在设置上述两个目录后运行：
34: 
35: ```powershell
36: .\deploy\start-backend.ps1
37: ```
38: 
39: 访问 `http://127.0.0.1:8000/health`。`start-local.cmd` 会在数据库配置有效且容器镜像一致时启动既有本地容器；它只停止本次启动的容器和应用。构建后的前端由后端同源提供；开发前端可在 `frontend/` 运行 `npm.cmd run dev`，实际模型动作使用同源工作区。
40: 
41: 低内存设备应分时运行数据库、应用、浏览器和固定预览，不并行启动全部验证服务。TASK117 合成验证在 Docker 暖机后逐次实测：单数据库／应用至少512 MiB、浏览器／第二数据库768 MiB、固定预览1024 MiB；连续两次低于256 MiB时拒绝新动作并关闭本次自有资源。这是受控验证的资源门，不是自动迁移或清理用户程序的权限。

43: ## 活动与首次学习
44: 
45: 活动配置参考 `config/activity.example.json`，在本机私有 `config/activity.local.json` 中分别配置活动限额和模型服务。示例占位值不会激活调用。服务密钥仅由配置指定的环境变量读取，不能填入目标、资料或浏览器。活动读取仅依赖存储层，零费新建需要活动限额层，首次学习及续问另需完整模型服务层。
46: 
47: 模型能力默认关闭。旧词项入口保留 `learning.v1`，集成入口使用 `learning.v2`、`teaching.v3` 与 `interview.v2`，须同时配置混合检索。输出限额分别最多256、2048、2048，且不超过活动与服务上限。公开示例的0和占位值有意不可用，坏配置会显示对应原因。
