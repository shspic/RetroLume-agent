## 2. 背景、问题与现有方式

**RetroLume 是以用户原始资料为上下文、以可追溯证据为基础、能根据练习反馈调整学习活动，并提供模拟面试的通用教育工作台。**

| 原始问题 | 期望结果 | 当前证据 |
| --- | --- | --- |
| 学习过程中上下文缺失 | 围绕个人资料和学习记录持续推进活动 | 提出者需求陈述；尚无具体使用记录 |
| 扩展资料不足 | 获得相关、可信且可使用的书单、资料与网站内容 | 尚未验证的用户问题假设 |
| 学习目标与路径不清晰 | 得到与资料、目标及诊断关联的学习路径 | 尚未验证的用户问题假设 |
| 错误无法归因 | 获得有依据的反馈和针对性复测 | 尚未验证的用户问题假设 |
| 抽象概念难理解和记忆 | 用交互 HTML 帮助理解并通过练习检查结果 | 尚未验证的用户问题假设 |
| 需要模拟面试 | 以自己的资料和目标完成面试练习及反馈 | 用户明确的产品需求，效果尚未验证 |

当前替代方式、发生频率、严重程度、已造成的损失和其他学生的反馈均未提供。不将需求陈述伪装成已有使用数据，也不将个人设想外推为目标人群的普遍事实。

## 4. 用户、场景及问题证据

目标用户是高中生和大学生，首个实际使用者为项目提出者本人。产品不固定学科、课程或面试方向；每次活动通过资料、目标及必要追问确定具体范围。

真实使用场景候选：阅读课程材料后练习、根据错题解释和复测、学习抽象概念、根据简历或其他材料模拟面试。场景来自用户描述，不代表已有频率或效果数据。

最低成本验证建议已随确认单获得方向确认：选择本人实际要用的学习资料和面试材料，记录现有做法、困难、预期结果及可核查答案；覆盖概念理解、可核算问题、操作/程序推理、开放式面试等不同任务类型。样例验证不限定产品学科，也不能证明全学科有效。公开服务前再核实其他目标用户的需要。

## 5. 核心流程与结果

**资料 → 理解与诊断 → 学习目标与路径 → 练习 → 反馈 → 交互解释 → 复测 → 更新路径。**

从上传资料开始，由系统整理、识别意图、诊断并追问必要缺口。用户不必预先手工完成知识整理。原始资料决定学习范围；正确性结合课程规范、可信资料和可验证计算；冲突显式呈现。

模拟面试的最低可用流程为：资料与目标 → 提问 → 用户回答 → 必要追问 → 有依据的反馈，首先通过文字完成。

错误归因区分证据支持的判断与待验证的可能原因；证据不足时允许追问、追加练习或暂不判断。学习进度需要保存；单文件失败可以替换或跳过，其他成功资料继续可用。任务达到上限或被中断时，结果和下一入口可被理解。

以上是产品行为，不指定内部 Agent 拓扑、数据库、接口或实现框架。

## 6. 当前范围与优先级

Must = 必须具备；Should = 应该具备、逐项验证后纳入；Could = 可以具备；Later = 延后。Should/Could 不得静默改成首版硬性验收项，也不得当作已经删除。

| 层级 | 范围 |
| --- | --- |
| Must | 文本输入、Markdown、可提取文字的 PDF；完整学习闭环、知识库与连续上下文、证据定位、必要追问、错误反馈、复测和路径更新 |
| Must | 本地交互 HTML、学习进度保存、文字模拟面试、单文件失败隔离、替换/跳过、超时与中断处理、任务循环上限 |
| Should | 图片、Word、PPT、Excel、扫描件处理；可信扩展资料推荐及内容使用，逐项验证后纳入 |
| Could | 首版语音输入与播报 |
| Later | 实时语音面试增强；功能完善后考虑部署上线或公开服务 |

更多输入便利性后置的已知代价是资料处理与面试真实感有限；当本人真实使用的主要资料或交互方式依赖这些能力时，需显式重评优先级。原始多模态愿景保留。

## 11. 成功标准与项目成立条件

首版成功方向是本人能使用真实任务范围内的资料完成学习主链和文字面试，并能核查关键依据、保存进度、处理部分失败，而不只是获得一次回答。

项目成立需要至少验证：支持范围内资料可被正确解析和定位；回答与诊断有依据；交互解释内容可核查；复测能以可解释方式更新活动；任务可按上限停止并保留可用成果。

初步验收包括：合法资料完成主链、混合成功/失败文件、目标缺失、证据不足、来源冲突、可核算结果、交互 HTML、超时/取消/预算耗尽、完整文字面试。以上均尚未执行，样本数量、阈值和正式检查编号后续确定。
